# 문서 작업 규칙

## 문장

- 한 문장에 한 생각을 쓴다. 짧게, 능동태로 쓴다. 한 개념에는 한 단어를 쓴다.
- 결정의 이유, 수치, 조건은 줄이거나 빼지 않는다.
- 제품명과 코드 식별자는 바꾸지 않는다.
- 날짜는 `YYYY-MM-DD`로 쓴다. 확인하지 않은 내용은 따로 적는다.

## 남길 문서

필요한 문서만 둔다. 쓰지 않는 문서, 대체된 시안, 보관본, 백업은 남기지 않고 지운다. 이전 내용은 Git 이력으로 확인한다.

## 그림과 캡처

- 그림은 SVG로 그리고, 같은 이름의 PNG(2배 해상도)를 함께 둔다. README와 PPT는 PNG를 쓴다.
- 색은 `DESIGN.md`의 토큰을 쓴다. 배경은 흰색으로 둬서 GitHub 어두운 테마에서도 읽히게 한다.
- 화면 캡처는 `assets/screens/`에 1440×900 PNG로 둔다. 화면이 바뀌면 다시 찍는다.
- PPT·영상 같은 큰 파일은 저장소에 넣지 않는다. 링크만 `team.md`에 적는다.

- 사실 하나는 문서 하나에만 적는다. 화면 규칙은 루트 `DESIGN.md`가 기준이다. 다른 문서는 링크한다.
- 새 문서를 만들기 전에 위 문서에 넣을 수 있는지 먼저 본다.
- 문서를 옮기거나 지우면 모든 상대 링크와 README의 문서 표를 고친다.

## ADR

ADR은 되돌리기 어려운 결정과 그 이유를 남긴다. 아래 세 조건을 **모두** 만족할 때만 쓴다. 기준은 Matt Pocock의 `domain-modeling` 스킬을 따른다.

1. **되돌리기 어렵다.** 나중에 바꾸면 비용이 크다. 예: 배포한 원장과 회로, 공개 API 계약, 저장 방식, 외부 서비스.
2. **맥락 없이는 의아하다.** 코드만 본 사람이 "왜 이렇게 했지?"라고 묻는다.
3. **실제로 고른 결과다.** 검토한 대안이 있었고, 특정한 이유로 하나를 골랐다.

하나라도 아니면 ADR을 쓰지 않는다. 쉽게 되돌릴 수 있으면 되돌리면 된다. 의아하지 않으면 묻는 사람이 없다. 대안이 없었으면 남길 이유가 없다.

ADR이 되는 결정의 예:

- 구조: API 계층([0004](adr/0004-api-layers.md)), 웹 앱 구성([0006](adr/0006-seller-console-and-single-web-app.md))
- 바꾸는 데 오래 걸리는 기술 선택: Vercel 함수와 Upstash([0002](adr/0002-vercel-functions-and-upstash.md)), Sepolia 원장([0003](adr/0003-sepolia-ledger.md))
- 원장, 회로, 공개 API의 계약: 등록한 기준으로 판정하는 원장 v5([0005](adr/0005-ledger-v5-registered-rules.md)), API 키의 인증과 범위([0008](adr/0008-api-keys.md))
- 범위와 경계. 하지 않기로 한 것도 남긴다: 고객은 FINVERIC 화면을 쓰지 않는다, 제조사는 client가 아니다([0006](adr/0006-seller-console-and-single-web-app.md))
- 일부러 일반적인 방법을 따르지 않은 것: 응답 스키마를 문서에만 쓴다([0007](adr/0007-openapi-and-channel-sample-app.md))
- 코드에 보이지 않는 제약: 법규, 외부 계약, 실행 시간 한도

ADR이 아닌 것은 아래에 적는다.

| 내용 | 위치 |
| --- | --- |
| 화면 규칙(색, 글자, 배치, 문구, 컴포넌트) | 루트 `DESIGN.md` |
| 폴더 구조, 코드 규칙, 작업 방법 | 그 폴더의 `AGENTS.md` |
| 제품 범위, 업무 규칙, 완료 기준 | `prd.md` |
| 배포 구성과 순서 | `deploy.md` |
| 무엇을 왜 바꿨는지(폴더 이동, 이름 변경, 리팩터링, 의존성, 버그 수정) | 커밋 메시지 |

### 형식

- 위치는 `adr/`, 파일 이름은 `NNNN-주제.md`다. 번호는 가장 큰 번호에 1을 더한다.
- 반드시 쓴다: 제목, 날짜와 상태 한 줄, 맥락과 결정과 이유. 짧으면 한 문단으로 쓴다.
- 값이 있을 때만 쓴다: 대가(뒤따르는 영향이 분명하지 않을 때), 검토한 대안(거절한 이유가 분명하지 않을 때).
- 바꾼 파일 목록은 쓰지 않는다. 커밋이 기록한다.
- 상태는 `제안`, `결정됨`, `대체됨`이다. 결정을 바꾸면 새 ADR을 쓰고, 이전 ADR의 상태 줄에 새 ADR을 링크한다.
- 작업이 기존 ADR과 어긋나면 그 ADR 번호를 밝히고, 다시 정할 이유를 적는다. 말없이 덮어쓰지 않는다.
