## 최종 제출 자료

1. **발표 자료.** PDF 또는 PPTX로 제출한다. 문제와 시장, 해결 방식과 비즈니스모델, 설계와 현장 시연, 검증과 향후 계획 순으로 설명한다.
2. **작동하는 MVP.** 서비스 주소와 이용 안내 또는 로컬 실행 절차를 제공한다. 핵심 사용자 흐름과 블록체인 기능을 각각 하나 이상 현장에서 보여 준다. 실제로 구현한 범위와 모의 처리 범위를 표시한다. 공지는 공개 테스트넷을 권장하고 로컬 블록체인도 허용한다.
3. **GitHub 저장소.** 평가자가 소스, README, 개발 이력에 접근할 수 있게 한다.
4. **계약과 검증 자료.** 계약 소스, 배포 환경, 주소, 탐색기 Verified 링크 또는 재현 자료를 제출한다. 기능 테스트의 기대 결과와 실제 결과를 적는다. 정상 처리, 권한, 입력 오류, 중복 요청을 확인할 수 있는 근거를 남긴다. 재현 자료에는 컴파일 설정, 배포·실행 방법, 동작 기록을 넣는다.
5. **약 3분 시연 영상.** 실제 MVP를 녹화한 MP4 또는 평가자가 접속할 수 있는 링크를 제출한다. 현장 발표에서는 직접 시연하며 영상도 재생할 수 있다.
6. **개발 계획과 팀 참여 기록.** 목표, 일정, 완료 현황, 향후 계획을 정리한다. 팀원별 성명, 역할, 실제 수행 내용과 문서·화면·코드·커밋·테스트 등 근거를 넣는다.
7. **설계와 AI 활용 기록.** 주요 화면, 사용 흐름, 구조도를 넣는다. AI 도구, 활용한 작업, 반영한 결과, 팀이 수정한 내용과 이유, 확인·테스트 결과를 적는다.

팀 대표 한 명이 각 발표 수업 시작 전에 제출한다. 메일 본문에 모든 파일과 링크를 한 목록으로 정리한다. 다른 계정이나 새 환경에서 링크 접근과 실행을 확인한다. 제출 주소는 원본 12쪽에 있다. 제목은 `블록체인개론_팀명_프로젝트명_중간점검` 또는 `블록체인개론_팀명_프로젝트명_최종발표` 형식을 쓴다.

원본 3쪽은 시연 영상을 ‘추가가능’으로 표시한다. 8쪽의 최종 필수 제출 목록에는 약 3분 영상이 포함된다. 최종 제출 준비는 8쪽의 목록을 기준으로 정리했다.

## 평가 기준

팀 결과물은 100점 만점이다. 같은 팀원에게 같은 점수를 적용하며 전체 성적의 30%에 반영한다.

| 평가 항목 | 배점 |
| --- | ---: |
| 문제 정의와 해결 가치 | 15 |
| 혁신성과 블록체인 적합성 | 10 |
| MVP 완성도와 검증 | 30 |
| 비즈니스모델과 확장성 | 10 |
| 사용성과 디자인 | 5 |
| 기술 설계와 코드 관리 | 10 |
| 팀 협업과 AI 활용 | 10 |
| 발표와 질의응답 | 10 |

MVP 30점은 핵심 사용자 흐름의 실제 작동 15점, 블록체인 연동과 동작 증거 5점, 정상·권한·오류 상황 테스트 10점으로 나뉜다. 현장 오류가 생기면 녹화본, 소스코드, 재현 자료를 함께 확인한다.

시장 자료에는 출처와 기준 시점을 적는다. 실제 측정 결과와 예상 효과를 구분한다. FINVERIC 팀 자료의 위치는 [팀 운영과 자료 정리](../team.md)에 있다.
