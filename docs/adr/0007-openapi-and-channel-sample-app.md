# 0007. 판매 채널은 API 문서와 별도 예시 앱으로 보여 준다

2026-11-13 · 결정됨(2026-11-13 구현) · [0006](0006-seller-console-and-single-web-app.md)의 client 메뉴(판매 채널)와 고객 검증 화면 위치를 바꾼다

## 맥락

[0006](0006-seller-console-and-single-web-app.md)은 판매 채널 화면(펀드 찾기, 가입하기, 내 가입 기록, 가입 기록 확인)을 판매사 콘솔(client)의 메뉴 그룹으로 두었다. 고객 화면과 판매사 업무 화면이 한 사이드바에 섞였다.

실제 판매사는 FINVERIC 화면을 고객에게 보여 주지 않는다. 판매사의 증권사 앱이나 은행 앱이 FINVERIC API를 부르고, 고객 화면은 판매사가 만든다. 판매사 개발자에게 필요한 것은 API 계약이다. 사용자는 두 가지를 요청했다.

- 증권사 앱에서 고객이 보는 화면은 새 탭에서 따로 연다.
- OpenAPI를 지원한다.

## 결정

- **API는 OpenAPI 3.1 문서를 제공한다.** `GET /api/openapi.json`이 문서이고, `GET /api/docs`가 그 문서를 그리는 화면이다. 두 경로는 접근 코드 없이 열린다. 문서는 Fastify에 등록한 경로의 스키마에서 만든다(`@fastify/swagger`).
- **API 분류(태그)는 하는 일로 정한다.** 증권사 앱이 고객 한 명을 처리할 때 부르면 `판매 채널 연동`, 판매사 직원이 콘솔에서 쓰면 `판매사 콘솔`, 상태 확인과 문서는 `시스템`이다.
- **판매 건 동작은 동작마다 경로가 따로 있다.** `/api/sales/:id/action/<동작>`이다. 동작마다 분류와 설명이 다르다. 없는 동작은 404다.
- **판매 채널 화면은 별도 페이지 `/channel/`(증권사 앱 예시)다.** FINVERIC API로 만든 고객 화면 예시다. 화면은 상품 목록, 상품 상세, 가입하기, 내 가입 기록, 가입 기록 확인이다. 판매사 콘솔의 사이드바 하단에서 새 탭으로 연다. API 문서도 같은 곳에서 새 탭으로 연다.
- **판매사 콘솔 메뉴는 판매사 업무만 둔다.** 대시보드, 진단 기준, 상품 관리, 판매·검토, 위험 신호, 온체인 처리다. 예전 주소 `/client/channel/*`는 `/channel/*`로 보낸다.
- **고객 검증 화면은 `/channel/verify`다.** 0006과 같이 판매사 API를 쓰지 않고 브라우저가 지정 RPC로 원장과 대조한다.
- **진입 화면의 역할 카드는 그대로 두 개다.** 판매사 콘솔과 감독기관이다. 증권사 앱 예시는 고객용 FINVERIC 화면이 아니므로 역할 카드로 두지 않는다.

## 이유

- 판매사가 FINVERIC을 붙이는 방법은 API다. API 문서가 그 계약을 보여 준다. 화면 예시는 같은 API로 고객 흐름을 만들 수 있다는 증거다.
- 고객 화면을 별도 페이지로 두면 판매사 업무 메뉴와 섞이지 않는다. 판매사 직원과 고객의 화면이 실제 서비스처럼 나뉜다.
- 새 탭으로 열면 콘솔과 고객 화면을 나란히 놓고 같은 판매 건을 확인할 수 있다.
- 등록한 경로에서 문서를 만들므로 경로와 문서가 어긋나지 않는다. 통합 검사가 모든 API 응답을 문서의 응답 스키마와 대조한다.

## 대가

- 웹 페이지가 네 개가 된다. Vite 입력, 개발 서버 대체 경로, Vercel 경로가 하나씩 늘어난다.
- 응답 스키마는 문서 전용이다. Fastify의 응답 직렬화에는 쓰지 않는다. 응답 형식이 바뀌면 `packages/core/src/api.ts`의 응답 스키마도 고쳐야 한다. 통합 검사가 어긋남을 찾는다.
- 새 탭은 `noopener`로 연다. 접근 코드가 필요한 외부 시연에서는 새 탭에서 접근 코드를 다시 입력한다.
- 증권사 앱 예시도 FINVERIC이 만든 화면이다. 실제 판매사 앱이 아니라는 점을 발표에서 구분한다.

## 검토한 대안

- **판매 채널을 콘솔 메뉴로 유지(0006).** 페이지가 적다. 고객 화면과 판매사 업무 화면이 한 사이드바에 섞인다.
- **API 문서만 제공하고 화면 예시는 없앤다.** 가장 단순하다. 고객 흐름(진단, 설명, 숙려, 검증)을 시연에서 보여 줄 수 없다.
- **swagger-ui로 문서 화면을 만든다.** 기능이 많다. 정적 파일이 필요해서 Vercel 함수 번들과 경로 설정이 복잡해진다. 화면 색과 글꼴이 DESIGN.md와 다르다.
