# 0001. 웹을 사용자 집단별 앱 두 개로 나눈다

2026-11-12 · 결정됨

## 맥락

FINVERIC은 B2B·B2G 서비스다. 고객사는 운용사, 판매 증권사, 준법 담당자다. 감독기관과 외부 검증자는 기록을 검증한다. 투자자는 FINVERIC 화면을 직접 쓰지 않는다. 투자자는 증권사 앱에서 가입하고, 그 앱이 FINVERIC API에 연결한다.

이전 웹은 한 사이트의 사이드 탭에 사용자 메뉴와 관리자 메뉴를 함께 두었다. 이 구성은 두 가지를 흐렸다. 투자자가 FINVERIC 사용자처럼 보였다. 검증자 화면이 판매사 업무 화면 옆에 있었다. `App.tsx` 한 파일이 2,703줄이었다.

## 결정

| 앱 | 대상 | 화면 |
| --- | --- | --- |
| `apps/client` | 운용사·증권사·준법 담당자 | 상품·문서 관리, 판매·검토 현황, 온체인 처리, 판매 채널 시연 |
| `apps/auditor` | 감독기관·외부 검증자 | 독립 검증 |

- 판매 채널 시연은 client 앱에 둔다. "증권사 앱에서 고객이 보는 화면"으로 표시한다. 시연에서 진단과 가입 거래를 만드는 데 쓴다.
- 공통 화면 요소와 API 클라이언트는 `packages/ui`에 둔다. 판정·해시·검증 로직은 `packages/core`에 둔다.
- 두 앱을 같은 도메인에 배포한다. client는 `/client/`, auditor는 `/auditor/`다. 루트 `/`는 `/client/`로 보낸다. 두 앱이 같은 모양의 경로를 써서 URL만 보고도 대상이 드러난다.

## 이유

- 사용자 집단마다 메뉴와 첫 화면이 다르다.
- 기관 업무 코드가 검증 화면에 실리지 않는다.
- 시연에서 기관 창과 검증자 창을 나란히 띄워 같은 판매 ID를 보여 줄 수 있다.

## 대가

- 공통 패키지를 관리해야 한다.
- 개발 서버가 두 개다(5173, 5174).
- client에서 검증 화면으로 가는 링크는 다른 앱을 연다.
