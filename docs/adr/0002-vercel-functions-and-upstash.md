# 0002. API를 Vercel 함수로 실행하고 판매 기록은 Upstash Redis에 둔다

2026-11-12 · 결정됨

## 맥락

외부 시연은 맥미니 없이 동작해야 한다. 2026-11-12 기준 비공개 Sites 배포는 맥미니의 API, Anvil, 브리지, 임시 Cloudflare 터널에 의존한다. 터널 주소는 재시작할 때마다 바뀐다. 이전 계획은 Render에 API를 두는 것이었다. Render 무료 인스턴스는 쓰지 않을 때 멈춘다.

기말 MVP는 비상업적 과제다. Vercel Hobby는 비상업적 개인 사용을 허용한다. 저장소는 개인 계정의 비공개 저장소라서 Hobby에 연결할 수 있다.

## 결정

- 웹과 API를 모두 Vercel에 배포한다. API는 Fastify 앱 하나를 함수 하나로 실행한다.
- 빌드는 Build Output API v3 형식을 직접 만든다. API는 esbuild로 묶고 증명 키와 배포 설정을 함수에 넣는다.
- 판매 기록은 Upstash Redis에 둔다. 기록을 바꾸는 요청은 Redis 잠금 안에서 실행한다.
- 로컬은 지금처럼 파일 저장과 프로세스 안의 큐를 쓴다.

## 이유

- 함수 한도가 시연에 충분하다. 실행 시간 최대 300초, 2 GB/1 vCPU다. 함수 크기는 약 6.6 MB다.
- 같은 도메인에 두면 CORS와 API 주소 설정이 필요 없다. 프리뷰 배포도 그대로 동작한다.
- Vercel 함수는 인스턴스가 여러 개 뜰 수 있다. 파일은 다음 호출까지 남는다는 보장이 없다. 프로세스 안의 큐는 인스턴스 사이의 순서를 지키지 못한다. 그래서 공유 저장소와 잠금이 필요하다.
- Upstash는 HTTP로 호출한다. 클라이언트 라이브러리를 추가하지 않았다.

## 대가

- 외부 서비스가 두 개다(Vercel, Upstash). 둘 다 무료 한도가 있다. Vercel 월 Active CPU 4시간, Upstash 월 50만 명령이다.
- 기록을 바꾸는 요청은 한 번에 하나씩 처리한다. 다른 요청이 잠금을 잡고 있으면 최대 120초 기다린다.
- Sepolia 영수증 대기를 포함해 한 요청이 300초 안에 끝나야 한다.
- 실제 Vercel 배포는 아직 검증하지 않았다. [배포 문서의 미확인 항목](../deploy.md#아직-확인하지-않은-것)

## 검토한 대안

- **Render + Vercel 웹.** 무료 인스턴스가 유휴 시 멈춘다. 지속 디스크가 필요하다.
- **Vercel 웹 + 맥미니 API·Anvil(고정 터널).** 코드 변경은 가장 적다. 맥미니 의존이 남는다.
