# MVP 실행과 시연

2026-11-12. 현재 시연 환경은 로컬 Anvil이다. 외부 시연은 Vercel과 Sepolia로 배포한다. Sepolia 배포는 테스트 ETH 충전을 기다린다. [배포 문서](deploy.md)

웹은 두 앱이다. client 앱은 운용사·증권사·준법 담당자 화면과 판매 채널 시연을 제공한다. auditor 앱은 감독기관·외부 검증자의 독립 검증 화면이다. [결정 기록](adr/0001-web-apps-by-audience.md)

## 실행

Docker로 실행하면 Node 설치가 필요 없다.

```bash
docker compose up --build
```

Node로 실행하려면 프로젝트 루트에서 Node 22.x를 사용한다.

```bash
npm ci
npm run dev
```

[client 앱](http://127.0.0.1:5173), [auditor 앱](http://127.0.0.1:5174/auditor/), [API 상태](http://127.0.0.1:3001/api/health)를 확인한다. `npm run dev`는 기존 Anvil을 재사용한다. 원장 버전과 증명 키가 같으면 배포도 재사용한다. 원장 버전이나 증명 키를 변경하면 배포를 갱신한다. 로컬 계정은 Anvil의 공개 테스트 mnemonic에서 만든다. 역할마다 다른 주소를 쓴다.

**내 가입 기록**은 원장 v4에서 완료한 가입 건을 표시한다. v1·v2·v3 거래와 로컬 원본은 이전 원장 주소로 구분해 보존한다. 이전 원장에 연결할 수 있고 해당 배포가 검증 대상으로 등록되어 있으면 auditor 앱의 파일 검증 경로 `/auditor/?source=file`에서 보관한 v1·v2·v3 원본과 영수증을 대조할 수 있다.

## 발표 순서

1. **상품·문서 관리**에서 세 상품의 설명서 v1과 진단 규칙 v3을 등록한다. 운용사와 판매사의 거래 주소를 구분해 보여준다.
2. **판매 채널 시연 › 펀드 찾기**에서 균형성장 글로벌 펀드를 선택한다. 이 화면은 증권사 앱에서 고객이 보는 화면이다. 원금 손실 가능, 연 보수 0.68%, 운용사·판매사, 온라인 Ce를 확인한다.
3. 진단 한 회차를 마치고 **가입 중단하기**를 누른다. 임시 기록을 폐기하고 가입 이력과 원장에 가입 건이 생기지 않는지 확인한다.
4. 상품 상세에서 새 가입을 시작한다. 가상 답변 `손실 감내 어려움 / 펀드 투자 경험 있음`을 제출한다. 첫 회차는 안정형이다.
5. **답변 정정하기**에서 `일부 손실 감내 가능 / 여러 위험자산 투자 경험 있음`을 제출한다. 두 번째 회차는 적극형이다. 세 번째 답변 `일부 손실 감내 가능 / 펀드 투자 경험 있음`은 균형형이다. 세 회차를 임시 기록에 보관한다.
6. **판매·검토 현황**에서 세 회차를 검토하고 승인한다. 진단과 준법 승인 중에는 원장 거래를 제출하지 않는다.
7. **판매 채널 시연 › 가입하기**에서 상품 설명과 원금 손실 가능성을 확인한다. 상품이 성향보다 위험하다는 점과 직접 선택한 상품의 가입을 계속 원한다는 점을 별도로 확인한다. **확인하고 가입하기**를 누른다.
8. **온체인 처리**에서 `EnrollmentAuthorized`, `HigherRiskConfirmed`, `ConditionsVerified`가 같은 거래의 이벤트인지 확인한다. **판매 채널 시연 › 내 가입 기록**에서 가입이 완료됐는지 확인한다.
9. **auditor 앱의 독립 검증**에서 가입 이력의 한 건을 고른다. client 앱과 창을 나란히 띄우면 같은 판매 ID를 두 쪽에서 보여 줄 수 있다. 투자성향, 커밋먼트, 추가 위험 확인과 가입 완료 기록을 원장과 대조한다. 검증 영수증과 원본을 내려받아 파일 검증 경로에서도 확인한다. 변경한 사본으로 원본 불일치를 확인한다.
10. 모의 매입을 별도로 시연할 수 있다. 모의 결과를 반영한 뒤 `1,050,000원 ÷ 1,050원 × 1,000 = 1,000,000좌`를 확인한다.

다른 두 펀드에서도 온라인 Ce 클래스로 105만원 가입을 시연할 수 있다. 안정형으로 진단하면 단기채권 안정추구 펀드는 일반 설명을 확인한다. 글로벌 혁신기업 펀드는 추가 위험 안내도 별도로 확인한다.

자동 시연은 `npm run demo`로 실행한다. 세 상품의 가입을 각각 새 판매 ID에서 진행한다. 상품마다 가입 거래 한 건을 제출한다. 결과는 `.local/demo/v4/`에 저장한다. 웹을 새로고침하고 해당 가입 건을 선택한다. 독립 검증은 RPC를 직접 조회하고 파일은 브라우저에서 처리한다.

원장 공격은 이어서 `npm run demo:attacks`로 시연한다. 같은 판매 ID의 가입 완료를 재시도한다. 다른 판매 ID나 다른 상품에 증명을 재사용하고 공개 입력을 바꾼 증명도 제출한다. 실패 영수증 해시는 `.local/demo/v4/attacks.json`에 남긴다.

## 검증 절차

| 검사 | 확인할 내용 |
| --- | --- |
| Foundry 단계·권한 검사 | Verifier stub으로 고객 계정 권한, 필수 동의, 준법 서명, 중복 완료 거절을 확인한다. |
| 실제 회로·API 통합 검사 | 별도 Anvil에 Groth16 Verifier를 배포한다. 임시 기록 폐기, 진단 회차, 상품별 필수 동의, 가입 거래 한 건을 검사한다. |
| CLI와 브라우저 시연 | 실제 ZKP, 가입 거래 한 건, 독립 검증, 변경 탐지를 확인한다. 모의 매입은 별도 단계에서 확인한다. |
| 독립 검증 | 가입 이력에서 검증을 요청하면 선택한 건의 영수증과 원본만 판매사 API에서 가져온다. 파일 검증 경로는 판매사 API를 호출하지 않는다. 두 경로 모두 RPC에서 최종 거래의 송신자, 입력, 이벤트와 영수증을 대조한다. |
| 원장 공격 시연 | 중복 완료, 다른 판매 ID의 증명 재사용, 공개 입력 변경을 거절한다. |

`npm run contracts:test`, `npm test`, `npm run build`로 재현한다. 통합 테스트는 18545 포트와 별도 임시 디렉터리를 사용한다. 기본 시연 원장의 데이터를 바꾸지 않는다.

## Sepolia와 외부 배포

배포 순서, 환경 변수, 한도는 [배포 문서](deploy.md)를 따른다.

API는 배포 때 쓴 것과 **같은** 증명 키(zkey)와 WASM을 사용해야 한다. 증명 키를 교체하면 기존 Verifier와 맞지 않는다. 키 지문이 배포 설정과 다르면 API 시작과 Vercel 빌드를 거절한다. Sepolia 배포 뒤 `npm run release:sepolia`로 `deploy/sepolia/`에 배포본을 만들고 커밋한다.

## 오류와 복구

- **상품 등록 전 가입 거절.** 상품·문서 관리에서 선택한 상품의 설명서 v1과 진단 규칙 v3을 등록한다.
- **필수 기록 누락.** 선택한 상품의 설명 확인을 점검한다. 투자성향이 해당 상품의 기준보다 낮으면 추가 위험 확인이 필요하다. 세 번째 진단부터 준법 검토 승인도 필요하다. 재진단하면 필요한 확인과 승인을 다시 받는다.
- **영수증 대기:** 해시를 확인하고 기다린다. 거래를 다시 보내지 않는다. 온체인 처리에서 새로 조회한다.
- **RPC 연결 실패:** 네트워크 ID와 RPC 설정을 확인한다. 실패를 완료로 표시하지 않는다.
- **증명 키 불일치:** 기존 키를 복원하거나 새 Verifier와 원장을 배포한다. 기존 고객 파일의 원장 주소는 바뀌지 않는다.
- **로컬 초기화:** 서버를 종료한 뒤 `.local/`을 백업한다. 보관할 이력이 없을 때만 다른 디렉터리로 이동한다. 다음 실행은 새 원장을 배포한다.

원본을 잃으면 원장 해시로 내용을 복구할 수 없다. 별도 기관의 장기 보관은 후속 범위다. 증명 키는 단일 운영자의 시연용 trusted setup이다. 실제 운영용 MPC ceremony와 보안 감사는 수행하지 않았다.
