# client 앱 작업 규칙

운용사·증권사·준법 담당자(B2B)가 쓰는 앱이다. 화면을 고치기 전에 루트 [DESIGN.md](../../DESIGN.md)를 읽는다.

## 메뉴와 경로

앱은 `/client/` 아래에서 실행한다(Vite `base`, 라우터 `basename`). 아래 경로는 그 안의 경로다. 사이트 루트 `/`는 `/client/`로 보낸다.

| 묶음           | 경로                                                               | 화면                                                 |
| -------------- | ------------------------------------------------------------------ | ---------------------------------------------------- |
| 기관 업무      | `/`, `/review`, `/chain`                                           | 상품·문서 관리(첫 화면), 판매·검토 현황, 온체인 처리 |
| 판매 채널 시연 | `/channel`, `/channel/fund`, `/channel/enroll`, `/channel/records` | 펀드 찾기, 상품 상세, 가입하기, 내 가입 기록         |

- 판매 채널 시연은 "증권사 앱에서 고객이 보는 화면"이다. FINVERIC 사용자 화면처럼 보이게 만들지 않는다. 이 묶음의 문구는 해요체로 쓴다.
- 판매 채널 경로는 `src/links.ts`의 `channel`로 만든다. 경로 문자열을 화면에 직접 쓰지 않는다.
- 독립 검증은 auditor 앱에서 한다. `auditorUrl()`로 링크한다. 이 앱에 검증 화면을 다시 만들지 않는다.

## 코드

- 화면마다 `src/screens/` 아래 파일 하나를 둔다. 두 앱이 함께 쓰는 요소는 `packages/ui`로 옮긴다.
- API는 `packages/ui`의 `api()`로 부른다. 같은 도메인의 `/api`를 쓴다. 개발 중에는 Vite가 로컬 API로 넘긴다.
- 판정·해시·검증 계산은 `packages/core`를 쓴다. 화면에서 다시 구현하지 않는다.
- 개발 서버는 5173 포트, 주소는 `http://127.0.0.1:5173/client/`다. `npm run dev`가 auditor 주소를 `VITE_AUDITOR_URL`로 넘긴다.
