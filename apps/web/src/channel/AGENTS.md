# channel 페이지 작업 규칙

증권사 앱 예시다. 고객은 FINVERIC 화면을 쓰지 않는다. 고객은 증권사 앱을 쓴다. FINVERIC은 판매사에 API를 제공한다. 이 페이지는 그 API로 만든 증권사 앱의 예시다. 화면을 고치기 전에 루트 [DESIGN.md](../../../../DESIGN.md)를 읽는다. 업무 규칙은 [PRD](../../../../docs/prd.md)를 따른다.

## 경로

페이지는 `/channel/` 아래에서 실행한다(라우터 `basename`). 아래 경로는 그 안의 경로다.

| 경로                         | 탭        | 화면                            |
| ---------------------------- | --------- | ------------------------------- |
| `/`                          | 상품      | 상품 찾기                       |
| `/fund?product=`             | 상품      | 상품 상세                       |
| `/enroll`                    | 가입      | 가입하기                        |
| `/records`, `/records?sale=` | 내 가입   | 내 가입 기록 목록, 가입 건 하나 |
| `/verify`, `/verify?sale=`   | 기록 확인 | 가입 기록 확인                  |

- 경로는 `links.ts`로 만든다. 경로 문자열을 화면에 직접 쓰지 않는다.
- 판매사 콘솔의 이전 주소 `/client/channel/*`는 콘솔이 같은 쿼리로 이 페이지에 보낸다.
- 진입 화면과 판매사 콘솔은 이 페이지를 새 탭으로 연다.

## 화면 틀

- `Frame.tsx`가 틀을 만든다. 판매사 콘솔의 사이드 메뉴(`Shell`)는 쓰지 않는다.
- 맨 위 줄은 앱 밖의 표시다. "FINVERIC API 연동 예시"와 네트워크 배지를 둔다.
- 앱 머리글에는 증권사 이름을 쓴다. 이름은 판매 중인 상품의 `seller`다. 상품 상세와 가입 건 하나에서는 뒤로 가기를 둔다.
- 본문은 최대 480px 한 열이다. 좌우 여백은 24px다. 넓은 화면에서도 같은 한 열을 가운데에 둔다.
- 아래 탭 막대(상품, 가입, 내 가입, 기록 확인)는 모든 너비에서 쓴다.
- 탭과 선택 영역의 높이는 44px 이상이다. 주요 버튼은 `Button size="large"`(높이 56px, 반경 16px)다.

## 문구

- 해요체로 쓴다. 제목은 질문이나 현재 상태를 한 문장으로 쓴다.
- 본문에 블록체인 용어(원장, 블록, 거래 해시, 컨트랙트)를 쓰지 않는다. 필요하면 "기술 정보 보기"에 접어 둔다. 맨 위 줄의 네트워크 배지는 예외다.
- 실제 서비스처럼 만든다. 화면 문구에 "시연", "모의", "테스트용"을 쓰지 않는다. 발표용 조작(숙려 중 최종 확인 시도, 사후 변경 시도, 결제 기록 버튼, 답변을 바꾼 원본 내려받기)을 넣지 않는다. [발표 순서](../../../../docs/runbook.md#발표-순서)

## 단계 화면

가입, 상품 상세, 가입 건 하나는 같은 단계 화면 규칙을 따른다. 부품은 `flow.tsx`에 있다.

- 단계 머리글(`StepHeader`)은 화면 위에 붙어 있다. 왼쪽에 "이전"(돌아갈 수 있는 단계만), 가운데에 단계 이름과 진행("진단 2/6", "핵심 설명 3/5"), 오른쪽에 "중단"(청약 전만)을 둔다. 아래에 진행 막대와 상품 한 줄을 둔다.
- 단계가 바뀌면 화면 맨 위로 가고 새 단계 제목(`h2`, `tabIndex=-1`)에 초점을 옮긴다.
- 주요 동작은 단계마다 하나다(`PrimaryAction`). 아래 동작 막대(`ActionBar`)에 둔다. 640px 이하에서는 탭 막대 바로 위에 고정하고, 넓은 화면에서는 본문 끝에 둔다. 보조 동작(다시 진단, 철회, 내려받기)은 본문 안의 테두리 버튼이다.
- 처리 중에는 주요 버튼이 같은 자리에서 회전 표시를 보이고 누름을 무시한다(`PrimaryAction`의 `busy`). 버튼 아래 한 줄에 처리 이름을 쓴다(자리를 미리 잡는다). 처리 중에는 "이전"과 "중단"을 숨긴다. 화면 위쪽에 진행 띠를 넣지 않는다.
- 확인란, 숙려, 승인 대기처럼 아직 누를 수 없는 주요 버튼은 `blocked`다. 보조 버튼은 다른 처리 중에 `blocked`다. 네이티브 `disabled`를 쓰지 않는다. 누른 버튼의 초점이 남아야 한다.
- 오류는 머리글 아래에 띄운다(`Frame`의 알림). 본문을 밀지 않는다.
- 되돌릴 수 없는 동작(가입 중단, 청약 철회, 다른 상품 가입으로 진행 중인 신청 중단)은 `ConfirmDialog`(`packages/ui`, `size="large"`)로 먼저 묻는다. 안전한 선택이 주요 버튼이다. 탭을 옮기는 것은 묻지 않는다.

## 가입 절차

- 순서는 진단(한 화면에 한 문항) → 결과 → 적합성 → 핵심 설명 카드 5장 → 녹취 동의(대상만) → 청약 → 숙려 → 최종 확인 → 증명서다.
- 숙려 중에는 남은 시간이 끝날 때까지 최종 확인 버튼을 막는다. 철회는 언제든 할 수 있다.
- 청약 전에는 언제든 가입을 중단할 수 있다. 진단 회차는 원장에 남고 다음 가입에서 이어진다.
- 3회차 이상 진단한 고객의 청약은 판매사 관리자 승인 뒤에 한다. 승인은 판매사 콘솔(다른 탭)의 판매·검토에서 한다. "준법"은 쓰지 않는다.
- 승인을 기다리는 동안 청약 단계에 차분한 대기 상자를 둔다. 오류로 표시하지 않는다. 회전 표시는 상자에만 두고 "청약하기"는 `blocked`로 둔다. 가입 화면은 3초마다 판매 건을 다시 읽고, 탭으로 돌아오면(`visibilitychange`, `focus`) 바로 다시 읽는다. 승인되면 상자가 "승인을 받았어요"로 바뀌고 "청약하기"가 열린다. 청약은 고객이 누른다.
- 상품 카드의 "가입하기"와 상품 상세의 주요 동작은 그 상품의 가입에 바로 들어간다(`useStartEnrollment`). 같은 상품의 가입이 진행 중이면 그 단계로 돌아간다. 다른 상품의 청약 전 가입이 있으면 중단할지 묻는다. 청약한 가입은 내 가입 기록에 남는다.
- 탭을 옮겨도 가입은 이어진다. 진행 중인 신청 번호(`finveric-draft`)와 청약 전 화면 상태(`finveric-enroll:<판매 ID>`)를 `sessionStorage`에 둔다. 탭마다 따로 보관한다. 설명 카드를 본 시간도 떠날 때 보관한다.
- 가입이 확정되면 증명서 단계에 머문다. 주요 동작은 "내 가입 기록 보기", 보조 동작은 "가입 기록 확인하기"와 "증명서 내려받기"다.

## 데이터

- 자료는 `packages/ui`의 `api()`로만 읽고 쓴다. 응답 타입과 요청 본문은 `packages/core/src/api.ts`의 DTO를 쓴다.
- 오류는 `App.tsx`의 `customerMessage()`가 고객 문장으로 바꾼다. API 오류의 `code`(`offline`, `pending`, `unavailable`, `rejected`와 `ledgerError`)로 고른다. 원장·거래·해시·영수증 같은 말과 판매사 콘솔에서만 할 수 있는 안내를 고객에게 보이지 않는다. `code`가 없는 업무 규칙 오류는 API 문장을 그대로 쓴다.
- 처음 읽기에 실패하면 화면은 "불러오지 못했어요"를 보여 준다(`LoadState`의 `failed`). "불러오고 있어요"에 머물지 않는다.
- `App.tsx`가 설정, 진단 기준, 상품, 판매 건, 시연 고객의 회차를 한 번에 읽는다. 화면은 `run()`으로 처리를 부르고, 끝나면 모두 다시 읽는다. 시연 고객 번호는 `/api/config`의 `demoCustomer`를 쓴다.
- 가입 기록 확인(`/verify`)은 판매사 API를 부르지 않는다. `verifySale`(동적 import)로 지정 RPC의 원장과 대조한다. 결과는 `일치`, `불일치`, `기록 없음`만 쓴다.
- 판정(`isSuitable`, `isProtectedSale`)과 검증(`verifySale`)은 `packages/core`를 쓴다. 화면에서 다시 구현하지 않는다.

## 코드

- 다른 페이지 폴더(`src/client`, `src/auditor`, `src/entry`)에서 import하지 않는다. 판매사 콘솔과 함께 쓰는 표시 계산과 요소는 `packages/ui`에 둔다.

| 파일                          | 내용                                                    |
| ----------------------------- | ------------------------------------------------------- |
| `App.tsx`                     | 자료 읽기, 처리(`run`), 오류 문장, 진행 중인 신청, 경로 |
| `flow.tsx`, `flow.module.css` | 단계 머리글, 주요 동작, 아래 동작 막대, 가입 시작       |
| `Frame.tsx`                   | 예시 표시 줄, 앱 머리글, 아래 탭 막대, 오류·진행 표시   |
| `frame.module.css`            | 틀 스타일                                               |
| `links.ts`                    | 경로                                                    |
| `screens/`                    | 화면 5개                                                |
| `screens/channel.module.css`  | 상품 찾기, 상품 상세, 가입하기, 내 가입 기록 스타일     |
| `screens/customer.module.css` | 가입 기록 확인 스타일                                   |
