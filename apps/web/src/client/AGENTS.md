# client 페이지 작업 규칙

판매사 소비자보호 담당(B2B)이 쓰는 판매사 콘솔이다. 판매 채널 시연(증권사 앱 재현)도 여기에 있다. 화면을 고치기 전에 루트 [DESIGN.md](../../../../DESIGN.md)를 읽는다.

## 메뉴와 경로

페이지는 `/client/` 아래에서 실행한다(라우터 `basename`). 아래 경로는 그 안의 경로다.

| 묶음           | 경로                                                                                  | 화면                                                              |
| -------------- | ------------------------------------------------------------------------------------- | ----------------------------------------------------------------- |
| 판매사 업무    | `/`, `/rules`, `/products`, `/review`, `/signals`, `/chain`                           | 대시보드, 진단 기준, 상품 관리, 판매·검토, 위험 신호, 온체인 처리 |
| 판매 채널 시연 | `/channel`, `/channel/fund`, `/channel/enroll`, `/channel/records`, `/channel/verify` | 펀드 찾기, 상품 상세, 가입하기, 내 가입 기록, 가입 기록 확인      |

- 판매 채널 시연은 "증권사 앱에서 고객이 보는 화면"이다. FINVERIC 사용자 화면처럼 보이게 만들지 않는다. 이 묶음의 문구는 해요체로 쓴다.
- 가입 기록 확인(`/channel/verify`)은 고객이 증명서로 기록을 확인하는 모습을 보여 주는 테스트 화면이다. 판매사 API를 부르지 않고 브라우저가 지정 RPC로 원장과 대조한다. 결과는 `일치`, `불일치`, `기록 없음`만 쓴다.
- 판매 채널 경로는 `links.ts`의 `channel`로 만든다. 경로 문자열을 화면에 직접 쓰지 않는다.
- 감독기관 화면은 `/auditor/` 페이지다. `auditorUrl()`로 링크한다.
- 3회차 이상 진단한 고객의 청약 승인은 "관리자 승인"이라 쓴다. "준법"은 쓰지 않는다.

## 코드

- 화면마다 `screens/` 아래 파일 하나를 둔다. 여러 화면이 함께 쓰는 계산은 `signals.ts`, `traces.ts`, `questions.ts`처럼 이 폴더에 둔다.
- API는 `packages/ui`의 `api()`로 부른다. 같은 도메인의 `/api`를 쓴다.
- 판정·해시·검증 계산은 `packages/core`를 쓴다. 화면에서 다시 구현하지 않는다.
